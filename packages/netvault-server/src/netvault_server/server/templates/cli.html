Step 01

Install / Update

Install the lightweight local CLI, then keep it current from GitHub.

curl -fsSL https://raw.githubusercontent.com/iihciyekub/netvault/main/scripts/install.sh | bash
nv update
nv --version
Step 02

Login

Use the shared NetVault server account shown below. The token is saved locally for future commands.

nv login https://iiaide.com/nv --username polyu --password '!1@2#3Qwe'
nv status
nv logout
Step 03

Download

Download by one DOI, many DOI values, or a text file. Downloads run in parallel and resume automatically.

nv download 10.1016/j.ijpe.2018.04.006 --to ./downloads
nv download 10.1016/j.ijpe.2018.04.006 10.1234/example --to ./downloads
nv download --file ./dois.txt --to ./downloads
Step 04

Upload PDFs

Two commands are all you need. Put your PDFs in a folder (for example, papers). If you have a cli-downloads.csv, place it in that folder; NetVault finds it automatically, including for PDFs in subfolders.

1. Check the DOI matches first (no files are uploaded):

nv upload ./papers --dry-run

2. Upload when the preview looks correct:

nv upload ./papers

How automatic DOI matching works: NetVault checks the CSV's SHA-256 first, so a renamed PDF can still be identified. It then tries the original filename and file size, or a unique article title on the PDF's first page. Without a safe CSV match, NetVault checks PDF metadata, then the first two pages, and only then the filename. It recognizes known double-hyphen fingerprint suffixes on renamed files. With automatic CSV discovery, the server verifies candidate DOIs against article titles; reference-only DOIs are not treated as article identities. Ambiguous matches are not guessed. The PDF filenames stay unchanged.

Trust your CSV for scanned PDFs: Explicitly pass --csv ./cli-downloads.csv to accept the CSV's DOI/PDF pairs without PDF title or content verification. This works even when a scanned PDF has no readable text. Files must match a unique CSV record by SHA-256 or filename and byte size; title matching and PDF fallback are disabled. Unmatched or ambiguous files are reported as failures. PDF file checks, deduplication, and conflicts with existing DOI assignments still apply. DOI metadata is still fetched when enabled, but unavailable metadata does not block ordinary uploads. Force replacement still requires available DOI metadata.

Explicit CSV upload commands, single PDFs, or manual DOI
nv upload ./papers --csv ./cli-downloads.csv --dry-run
nv upload ./papers --csv ./cli-downloads.csv
nv upload ./paper.pdf
nv upload ./paper-a.pdf ./paper-b.pdf
nv upload ./paper.pdf --doi 10.1234/example

Use --csv whenever you want to trust the CSV's DOI/PDF pairs, even if it is inside the upload folder. CSV rows need file (or filename), doi, bytes (or size), and status=downloaded; sha256 is optional and supports renamed files. --dry-run checks matches locally without logging in, uploading, or writing a report.

Step 05

Advanced DOI tools

Admin-only tools for finding suspicious DOI identities and safely correcting the DOI attached to an existing PDF without replacing the PDF file.

nv doi-audit --limit 500
nv correct-doi 56240 10.1287/msom.2021.1032 --reason "Incorrect PDF DOI extraction" --dry-run
nv correct-doi 56240 10.1287/msom.2021.1032 --reason "Verified against the PDF"

Use a current DOI, PDF id, or SHA-256 as the first argument. The command previews metadata before applying the correction and keeps the PDF file, SHA-256, aliases, and correction history unchanged. Use --allow-title-mismatch only after independently verifying the DOI.
