Step 01

Install / Update

Install the lightweight local CLI, then keep it current from GitHub. This server runs NetVault v{{ app_version }}.

curl -fsSL https://raw.githubusercontent.com/iihciyekub/netvault/main/scripts/install.sh | bash
nv update
nv --version
Step 02

Login / Status

Replace the example username and password with your own credentials. Your login is saved locally. Run nv login to enter them when prompted.

nv login https://iiaide.com/nv --username example-user --password example-password
nv status
nv logout
Step 03

Upload PDFs

Preview first, then upload. Folders include all subfolders.

A unique DOI in PDF Document Info takes priority over cached hints, download indexes, manual DOI hints, filenames and page text. NetVault fetches metadata for that DOI and binds the PDF to it; unavailable metadata does not change its identity. Conflicting Document Info DOIs require correction. Without an Info DOI, the existing resolver applies.

nv upload ./papers --dry-run
nv upload ./papers

Without a Document Info DOI, NetVault automatically looks for cli-downloads.csv in the folder. PDF filenames stay unchanged.

Ordinary uploads leave local PDF bytes unchanged. To automatically add a missing DOI before uploading, opt in with --write-doi. Existing unique Info DOIs are left unchanged.

Automatically write a verified missing DOI
nv upload ./papers --write-doi --dry-run
nv upload ./papers --write-doi

The preview runs locally without online verification or PDF changes. It cannot confirm that a DOI is verified. The live command independently checks each eligible missing-DOI PDF on the server before writing.

Writing requires exactly one explicit first-page article DOI, an exact Crossref DOI match, title similarity of at least 0.98, and independent first-page author and year evidence. Reference-list DOIs, download URLs and journal, issue or volume DOIs are excluded. Title search alone, other metadata providers, filenames, cached hints, CSV pairs and successful uploads cannot authorize a write. This conservative rule can still require review for preprints or version ambiguity.

An existing unique Info DOI is unchanged and follows ordinary upload rules, including signed PDFs. Conflicting or invalid DOI fields, encrypted or signed files needing a DOI, insufficient evidence and verification failures preserve the source and stop that file's upload.

A successful write creates filename.pdf.nv-doi-<original-sha256>.bak beside the source, validates an incremental temporary file and the unchanged source hash, then atomically replaces the source. Upload uses the new SHA-256. The report records verification, original/new hashes and the backup path. Write failures stop that file's upload.

--write-doi cannot be combined with --csv, --no-crossref or --doi. Ordinary deduplication retains an existing same-DOI server copy, so downloads may differ from the locally tagged PDF. Add --force to request canonical replacement; successful registry metadata is still required.

Run the same upload command to continue. NetVault saves .netvault-upload.sqlite3 beside the PDFs, skips files already on the server and remembers confirmed DOI/title rejections. New or changed files are processed; temporary errors can retry. Keep this hidden file when copying a folder. Full run results are saved in nv-upload-report.json; --verbose shows individual errors.

Retry files and PaperDock integration
nv upload ./papers --retry-failed
nv upload ./papers --refresh-doi

--retry-failed selects failed, pending and review files from directory state, with the upload report as a fallback for older records. --refresh-doi resolves automatic DOI identities again and retries rejections while keeping user-confirmed hints. Document Info retains priority over those hints. Use it after correcting DOI evidence or changing server verification rules.

PaperDock reads this state when preparing a download list and checks which DOI/PDF hashes are already on the server. No extra command is needed. A server lookup failure is shown as unavailable rather than treated as a missing PDF.

Step 04

Download

Download a DOI or a list of DOIs. Server matches are checked first; progress counts only files still needed locally. Missing DOI values are summarized quietly.

nv download 10.1016/j.ijpe.2018.04.006 --to ./downloads
nv download --file ./dois.txt --to ./downloads

After an interruption, run the same command with the same --to directory. Verified complete files are skipped and .part files resume with checksum verification.

Downloads use 8 parallel workers by default. Admin downloads have no hourly count limit; regular users keep the server limit. If the limit is reached, run the same command later. Failure and pending details are saved to nv-download-report.json.

Step 05

Advanced Management

Literature Management

One command for local PDFs: preview first, add --rename to apply. Subfolders are included and no PDFs are uploaded.

1. Preview any folder — no ISSN needed:

nv identify ./papers

2. Rename and organize:

nv identify ./papers --rename

Know the journal? Add --issn for fast local matching:

nv identify ./papers --issn 0025-1909 --rename

Omit --rename from any example to preview. Matched PDFs get DOI filenames. Extra identical copies go into duplicates/ beside each source PDF. Full-vault misses go into that PDF's unidentifys/. Existing files are never overwritten.

--issn downloads one journal index once. Files absent from that index stay in place; check them later without --issn.

Offline index and content duplicates

Export once, then reuse the CSV without login or network requests:

nv export --issn 0025-1909
nv identify ./papers --index ./netvault-0025-1909.csv --rename

Index misses stay in place. Exports include accepted file aliases; add --primary-only for retained hashes. Exports keep existing CSVs and add a number to the filename if needed. Use the actual exported filename with --index.

For files with the same page content but different PDF bytes, add --check-content. This takes longer:

nv identify ./papers --check-content --rename

Each run writes a new netvault-index.csv report in the scanned folder. Use --report ./report.csv to choose a different new report.

CSV uploads and manual DOI

Explicit --csv is a separate trusted import mode that uses the CSV's DOI/PDF pairs, including scanned PDFs without readable text, instead of PDF DOI extraction. Files must match one CSV record by SHA-256 or filename and byte size. Unmatched or ambiguous files are reported as failures. Ordinary --doi hints apply only when Document Info has no DOI.

nv upload ./papers --csv ./cli-downloads.csv --dry-run
nv upload ./papers --csv ./cli-downloads.csv
nv upload ./paper.pdf --doi 10.1234/example

CSV rows need file or filename, doi, bytes or size, and status=downloaded. Optional sha256 supports renamed files. Preview with --dry-run before uploading. CSV imports cannot use --write-doi.

Read and write PDF DOI metadata

Read Document Info offline, then append a DOI to its custom /DOI field. The write preserves existing page objects and other Info fields. XMP is unchanged and does not participate in DOI identity.

nv pdf-meta read ./paper.pdf --json
nv pdf-meta write ./paper.pdf --doi 10.1234/example
nv pdf-meta write ./paper.pdf --doi 10.1234/corrected --replace

Use --output ./tagged-paper.pdf to keep the original. Correcting an existing different DOI requires --replace. This offline command records the supplied DOI without independently verifying the article. Writing changes the file hash; nv doi --set changes only a local hint and leaves PDF bytes unchanged. Use the verified missing-DOI upload option above for automatic supplementation.

DOI Audit and Correction

Admin-only tools for finding suspicious DOI identities and safely correcting the DOI attached to an existing PDF without replacing the PDF file.

nv doi-audit --limit 500
nv correct-doi 56240 10.1287/msom.2021.1032 --reason "Incorrect PDF DOI extraction" --dry-run
nv correct-doi 56240 10.1287/msom.2021.1032 --reason "Verified against the PDF"

Use a current DOI, PDF id, or SHA-256 as the first argument. The command previews metadata before applying the correction and keeps the PDF file, SHA-256, aliases, and correction history unchanged. Use --allow-title-mismatch only after independently verifying the DOI.
